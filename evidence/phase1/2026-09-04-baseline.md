与当前项目直接相关的要求：

6. 外部贡献者提交 PR 后，CI 需要维护者留下 `/ok to test` 才开始。
7. 当前 PR 模板要求对应 issue，并要求测试与文档状态说明。
8. 当前仓库文件中未找到面向外部贡献者的 DCO、CLA 或生成式 AI 专项条款；公开贡献前仍需再次检查 GitHub 页面及当时政策。

## CUDA 实际运行验证

源码：`evidence/environment/cuda_smoke.cu`

普通 PowerShell 中直接运行 `nvcc` 会失败，因为 `cl.exe` 未加入 PATH。进入 VS Build Tools 的 x64 环境后，用以下核心参数编译：

```text
nvcc -std=c++17 -arch=sm_89 cuda_smoke.cu -o cuda_smoke.exe
```

运行结果：

```text
CUDA_SMOKE_RESULT=42
```

结论：本轮已验证驱动、CUDA 编译器、MSVC host compiler、kernel launch、同步和 device-to-host 拷贝组成的实际 CUDA 闭环。编译过程中 CUDA 13.3 头文件在中文代码页 936 下产生 `C4819` 编码警告，不影响本次可执行结果；后续正式构建应使用 UTF-8 环境或相应 MSVC 编码选项，避免日志噪声。

## WSL2 状态

`C:\Windows\System32\wsl.exe` 存在，但本轮执行 `--version`、`--list --verbose` 和进入 Linux shell 的尝试均没有列出或进入发行版，而是返回 WSL 安装帮助。因此当前不能把 WSL2 Linux 工具链记为可用，也未验证 Linux 内的 GCC、CMake、Ninja、CUDA 或 GPU kernel。

## 官方 benchmark 方法边界

当前官方文档要求从 `benchmark` preset 构建 CUB NVBench benchmark；运行时建议保存 JSON 和 Markdown，并使用 entropy stopping criterion。修改前后比较应使用 NVBench compare 工具及噪声/显著性结果，不能用单次运行或 Nsight Compute replay 时间宣称加速。Nsight Compute profiling 需要 `-lineinfo`，且 profiler 的 `--set full` 会重复执行 kernel。

## 当前能做什么、缺什么、下一步

当前能做：

- 在 Windows + MSVC + CUDA 13.3 上编译和运行 `sm_89` CUDA 程序；
- 使用 CMake preset、Ninja、SASS 工具和 Nsight 工具；
- 进入第二阶段前先做小范围 CUB 配置和定向测试。

当前缺口：

- 尚无可用 WSL2 发行版；
- 尚未配置 CCCL preset、构建 CUB 测试或 benchmark；
- 尚未验证 Nsight Compute 性能计数器权限；
- 尚未选定具体算法或性能问题。

建议下一步：先决定是否建立 WSL2 Ubuntu 环境。若暂不安装，则在 Windows 上用已定位的 MSVC 和 Ninja 对 `cub-cpp20` 做最小配置与单一目标 smoke test；成功后再构建一个小范围官方 benchmark，并保存原始 JSON/Markdown 基线。
