# WSL2 环境建立记录（2026-09-04）

## 安装前检查

- Windows：Windows 11 家庭中文版，版本 `10.0.22631`，64 位。
- CPU 虚拟化：固件虚拟化、VM Monitor Mode Extensions 和 SLAT 均为可用。
- 可用空间：C 盘约 8.0 GiB、D 盘约 24.7 GiB、E 盘约 41.1 GiB、F 盘约 745.4 GiB。
- 旧版 inbox `wsl.exe` 只提供安装和在线发行版列表能力，不支持 `--version`、`--import` 或 `--location`。
- 在线列表可见通用 `Ubuntu`，但尚未安装任何发行版。

基于空间约束，不应把后续 Ubuntu 虚拟磁盘默认放到 C 盘。目标位置暂定为 `F:\WSL`，但需要先获得支持 `--location`/`--import` 的当前 WSL 版本。

## 本轮执行

执行：

```powershell
wsl.exe --install --no-distribution --web-download
```

结果：

1. `Virtual Machine Platform` 显示安装成功。
2. 获取新版 WSL 组件时返回 HTTP 403，未完成新版 WSL 安装。
3. `wsl --status` 返回退出码 50；`wsl --list` 仍不能列出已安装发行版。
4. 系统出现 `Component Based Servicing\RebootPending`，并存在 `PendingFileRenameOperations`。

## 当前状态与停止条件

- 尚未安装 Ubuntu。
- 尚未安装 Linux CUDA Toolkit。
- 没有在 WSL 内安装 NVIDIA Linux driver；后续也不得安装该 driver。WSL2 应使用 Windows 主机驱动映射出的 `libcuda.so`。
- 由于 Windows 功能安装后处于等待重启状态，本轮在此停止，不继续叠加 WSL/Ubuntu 安装。

## 重启后的下一步

1. 重新检查 WSL 功能、版本和已安装发行版。
2. 重试获取当前 WSL 组件；若在线安装仍返回 403，再选择 Microsoft Store/winget 或官方离线包路线。
3. 使用支持自定义位置的方式将 Ubuntu 安装到 `F:\WSL`，避免占用仅剩约 8 GiB 的 C 盘。
4. 用户完成首次 Linux 用户名和密码初始化后，再安装 GCC、CMake、Ninja、Git 和不带 Linux 显示驱动的 CUDA Toolkit。
5. 分别验证 WSL2、`nvidia-smi`、`nvcc` 和实际 Linux CUDA kernel。
